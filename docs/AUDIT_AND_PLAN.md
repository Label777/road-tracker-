## 2. Ограничения iOS — честно

1. **Непрерывный фоновый GPS не гарантирован.** Запись в фоне возможна только для *начатой* поездки (`allowsBackgroundLocationUpdates` + режим `location`), и только при разрешении «При использовании» с активной сессией или «Всегда». Если пользователь закрыл приложение свайпом — iOS прекращает обновления. Альтернатива: состояние поездки сохраняется после каждого события; при следующем запуске запись продолжается, а промежуток без точек считается по времени.
2. **Геозоны — максимум 20 регионов на приложение**, срабатывают с задержкой (обычно до нескольких минут), точность ~100–200 м; минимальный разумный радиус — 100 м (зашито ограничением в БД).
3. **Significant Location Change** — шаг ~500 м и реже, будит приложение в фоне, но не даёт трека.
4. **Уведомление «Начать поездку?» может быть пропущено.** Альтернатива реализована в машине состояний: если после выхода из «Дома» сработал вход в «Работу», создаётся *неподтверждённая* поездка (время = выход → вход), которая ждёт подтверждения во вкладке «История».
5. **Выход из дома ≠ поездка.** Автоопределение никогда не создаёт подтверждённую поездку само; возврат в исходную геозону отменяет подсказку; подсказка истекает через 2 часа.
6. **Фоновая синхронизация** — `BGAppRefreshTask` запускается по усмотрению iOS; гарантирована только синхронизация при открытии приложения и при появлении сети.
7. **Разрешение «Всегда»** iOS выдаёт в два шага (сначала «При использовании», позже — отдельный запрос). Запрашиваем постепенно, на этапе 3, с объяснением.

## 3. Архитектура

```
RoadTracker (iOS, SwiftUI, MVVM + сервисы)
├── App/            composition root (AppEnvironment), точка входа
├── Persistence/    SwiftData-модели, TripStore — единственная точка записи
├── Sync/           RemoteStore (протокол), Supabase-реализация, SyncManager, NetworkMonitor
├── Tracking/       TrackingCoordinator: машина состояний ↔ хранилище ↔ сервисы iOS
├── Features/       экраны: Главная, Поездка, История, Аналитика, Профиль
└── DesignSystem/   токены темы и общие компоненты

Packages/RoadTrackerCore (чистый Swift, без UIKit/CoreLocation — тестируется где угодно)
├── Model/     Money (копейки, без float), перечисления = enum'ы PostgreSQL
├── Domain/    время/паузы/полночь, гео-математика и фильтр трека, остановки,
│              адаптивная политика GPS, финансовая аналитика, прогноз,
│              калькулятор экономии, статистика контролёров (интервал Уилсона)
├── Tracking/  TrackingStateMachine — вся логика ручного/GPS/авто режимов
└── Sync/      политика очереди: схлопывание, порядок, бэкофф, LWW
```

Ключевые решения:

- **Local-first.** Изменение и операция синхронизации сохраняются одним `context.save()` — потерять одно без другого нельзя. Очередь хранится в SwiftData и переживает принудительное закрытие.
- **UUID создаются на устройстве** и являются первичными ключами в Supabase → повторная отправка — идемпотентный upsert, дублей нет.
- **Удаление — tombstone (`deleted_at`)**, чтобы удаление дошло до сервера и других устройств; физическая очистка — `purge_tombstones()` по расписанию.
- **Конфликты: last-write-wins по `updated_at`**, одинаково на клиенте (`ConflictResolver`) и на сервере (триггер `reject_stale_write`). Удалённая запись не «воскрешается» старой правкой.
- **Деньги в копейках (Int)**: никакой погрешности float в отчётах.
- **Часовой пояс сохраняется в поездке** → день поездки не «переезжает» при смене пояса; поездки через полночь корректно делятся; учтён перевод часов.
- **Машина состояний отслеживания — чистая и Codable.** Сервисы iOS (CoreLocation, уведомления) только исполняют её команды. Это делает поведение тестируемым и восстанавливаемым после выгрузки приложения.
- **Статистика контролёров — описание прошлого, а не прогноз**: доля + 95 % интервал Уилсона + размер выборки + уровень достоверности (< 10 наблюдений — «недостаточно данных»).

## 4. Безопасность и приватность

- В приложении только публичный **anon/publishable key**; доступ ограничивает **RLS** («только свои строки») на всех таблицах. `service_role` в клиент не попадает. Секреты — в `Config/Secrets.xcconfig` (в `.gitignore`).
- Дочерние записи ссылаются на родителя **составным FK `(id, user_id)`**: нельзя прикрепить сегмент к чужой поездке даже с чужим `trip_id` (проверено тестом).
- Сессия Supabase хранится библиотекой в Keychain и восстанавливается автоматически.
- Координаты пишутся **только во время поездки**; трек по умолчанию **не уходит в облако** (`settings.sync_track_points = false`) и удаляется через 30 дней.
- `delete_my_location_history()` и локальный аналог стирают треки и координаты наблюдений; `delete_my_account()` удаляет пользователя и каскадом все данные.

## 5. Отклонения от исходной схемы и почему

| Исходно | Сделано | Причина |
|---|---|---|
| `users` | `profiles` (+ `auth.users` Supabase) | Пользователи живут в `auth.users`; профиль создаётся триггером |
| `total_cost`, `cost` — без типа | `integer`, копейки | Точность расчётов |
| `controller_present`, `ticket_checked` | вычисляются из `outcome` (5 вариантов из ТЗ) | Нельзя записать противоречие («контролёра не было, но билет проверили») |
| — | `updated_at`, `deleted_at`, `user_id` во всех таблицах | Синхронизация, удаление, быстрый RLS |
| — | `trips.time_zone`, `paused_seconds`, `comment` | Полночь/пояса, паузы, комментарий из ТЗ |
| — | `trip_track_points` (опционально) | Трек в облако только по согласию |
| — | уникальный индекс «одна активная поездка» | Защита от дублей при пересечении геозон |
